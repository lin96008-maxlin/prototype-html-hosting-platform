# 产品经理的软件开发与上线流程

## 一条主线

需求确认 -> 本地实现 -> 自动测试 -> 业务验收 -> 合并主分支 -> 手动发布演示环境 -> 线上验收。

## 各阶段产物

| 阶段 | 需要确认的内容 | 产物 |
| --- | --- | --- |
| 需求 | 用户、场景、范围、验收标准 | PRD 或任务说明 |
| 设计 | 页面结构、状态、权限、异常处理 | 原型与交互说明 |
| 开发 | 功能实现、数据库变更、配置变化 | 代码与 Migration（数据库迁移） |
| 测试 | 关键流程、权限、兼容性、回归 | 测试结果 |
| 发布 | 版本、环境变量、回滚方式 | 可追溯部署记录 |
| 验收 | 新域名上的真实流程 | 验收结论与问题清单 |

## 本项目检查命令

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

页面改动还需要运行 Playwright（浏览器自动化测试），并在桌面与窄屏尺寸检查布局、文字和交互。

## 发布控制

- `main` 分支提交自动执行 `持续集成检查`，不会自动连接服务器。
- 只有新仓库 `demo` 环境配置完成后，才手动执行 `手动部署演示环境`。
- 发布前确认新数据库为空或仅包含本项目演示数据。
- 发布失败时保留上一可用版本，不清空数据卷。

## 产品经理重点验收

1. 注册、登录、退出和修改密码。
2. 上传、更新、预览、下载和删除原型。
3. 公开广场与密码分享。
4. 部门、成员、角色、分类和邀请码权限。
5. 数据统计、空状态、错误提示和窄屏可用性。
