# 备份与恢复说明

## 备份范围

当前 `backup` 容器使用 Restic（增量备份工具）保存 PostgreSQL `pg_dump`，默认每天执行一次，保留最近 7 个每日快照。

原型源文件和预览图位于 `prototype_data` 数据卷，需要在新环境另外配置异机文件备份。数据库快照和原型文件缺一不可。

## 日常检查

```bash
docker compose exec -T backup /usr/local/bin/backup-healthcheck.sh
docker compose exec -T backup restic snapshots
```

GitHub Actions 的 `手动备份巡检` 只连接新仓库 `demo` 环境中配置的服务器，可选择：

- `check`：只读检查备份状态与磁盘空间。
- `verify`：把最新快照恢复到临时数据库并核对记录，不覆盖正式数据。

## 恢复原则

- 先恢复到临时目录和临时数据库。
- 验证账号、项目记录、版本记录与原型文件数量一致。
- 得到单独确认后，才能安排正式恢复窗口。
- 不得把测试快照覆盖到现有数据库、上传目录或持久化卷。

## 新环境必须补齐

1. 为 `prototype_data` 配置加密异机备份。
2. 备份目标使用本项目新账号与新密钥。
3. 至少每月执行一次隔离恢复演练。
4. 监控最后成功时间、仓库完整性和磁盘剩余空间。

本项目不包含旧环境备份、云账号、存储地址或恢复凭据。
