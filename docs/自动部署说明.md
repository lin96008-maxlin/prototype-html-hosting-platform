# 自动部署说明

## 当前状态

仓库只提供 `持续集成检查`：提交到 `main` 或创建 Pull Request 时，自动运行代码检查、类型检查、单元测试和生产构建。仓库不会连接或部署到任何服务器。

## 推荐发布方式

1. 等待持续集成检查通过。
2. 在目标服务器使用独立目录、`.env`、数据库、Docker Compose 项目名和数据卷。
3. 运行 `docker compose up -d --build`。
4. 等待 `/manage/api/health` 返回成功后，再切换反向代理流量。
5. 保留上一版本和数据库备份，失败时只回滚应用和新增网关配置。

如果需要 GitHub Actions 自动部署，应在自己的 Fork 中新增工作流，并使用独立的 GitHub Environment、部署账号和密钥。不要把服务器地址、SSH Key 或实际环境变量提交到仓库。

## 安全边界

- 配置文件和密码只保存在目标服务器或使用者自行创建的 GitHub Environment。
- 制品不包含 `.env`、数据库文件、上传原型或备份仓库。
- 未完成新域名解析和新服务器初始化前，不执行发布。
