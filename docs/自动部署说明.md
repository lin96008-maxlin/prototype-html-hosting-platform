# 自动部署说明

## 当前状态

新仓库包含两类 GitHub Actions（自动化流水线）：

- `持续集成检查`：提交到 `main` 或创建 Pull Request 时，自动运行代码检查、类型检查、单元测试和生产构建。
- `手动部署演示环境`：仅能手动触发，输入 `deploy` 后才会构建制品并尝试连接新演示服务器。

当前仓库不预设真实域名、服务器地址或密钥，因此不会自动部署到任何既有环境。

## 新仓库配置

在 GitHub 仓库创建名为 `demo` 的 Environment（环境），再配置：

| 类型 | 名称 | 用途 |
| --- | --- | --- |
| Variable | `DEPLOY_HOST` | 新演示服务器地址 |
| Variable | `DEPLOY_PORT` | 新服务器 SSH 端口 |
| Variable | `DEPLOY_USER` | 新部署账号 |
| Secret | `DEPLOY_SSH_KEY` | 仅用于新服务器的私钥 |
| Secret | `DEPLOY_KNOWN_HOSTS` | 新服务器主机指纹 |

不要复用旧服务器的密码、SSH Key、账号或主机指纹。

## 发布方式

1. 确认 `持续集成检查` 已通过。
2. 打开 Actions，选择 `手动部署演示环境`。
3. 输入 `deploy` 并运行。
4. 流水线生成独立制品，上传到新服务器，再调用 `/usr/local/sbin/prototype-demo-deploy`。
5. 健康检查失败时，部署脚本应保留上一可用版本。

## 安全边界

- 配置文件和密码只保存在新服务器与 GitHub `demo` 环境。
- 制品不包含 `.env`、数据库文件、上传原型或备份仓库。
- 未完成新域名解析和新服务器初始化前，不执行发布。
