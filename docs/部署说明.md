# 部署说明

## 部署目标

为“原型托管平台demo”创建一套完全独立的演示环境，包括新域名、新数据库、新 Docker Compose 项目、新数据卷和新部署账号。

## 环境要求

- Ubuntu 22.04 或更高版本
- Docker Engine 与 Docker Compose Plugin
- 可用的 HTTPS 域名
- 最少 2 核 CPU、4GB 内存；磁盘大小按原型文件规模评估

## 配置步骤

1. 将代码放入新服务器独立目录。
2. 参考 `.env.example` 创建服务器本地 `.env`。
3. 为以下字段生成互不相同的新值：
   - `POSTGRES_PASSWORD`
   - `SESSION_SIGNING_SECRET`
   - `SHARE_PASSWORD_ENCRYPTION_KEY`
   - `BACKUP_REPOSITORY_PASSWORD`
   - `BOOTSTRAP_SUPER_ADMIN_PASSWORD`
4. 将 `SITE_DOMAIN`、`ROOT_DOMAIN`、`MANAGE_URL`、`DEMO_URL` 改为新域名。
5. 启动独立环境：

```bash
docker compose up -d --build
```

6. 检查健康状态：

```bash
docker compose ps
curl --fail https://你的新域名/manage/api/health
```

## 数据边界

- 首次启动只执行 `database/migrations`，不得导入旧生产数据库。
- 上传目录、PostgreSQL 数据卷和 Restic 仓库均由本项目 Compose 创建。
- `.env` 不提交到 Git，不复制到日志或文档。

## 反向代理

默认可使用 Compose 中的 Caddy profile：

```bash
docker compose --profile standalone-proxy up -d
```

已有统一网关时，不启用 `standalone-proxy`，并为本项目单独配置网络或本机反向代理端口。不要连接或复用其他项目的数据库、数据卷和密钥。

## 上线前检查

- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 全部通过
- 新域名 HTTPS 正常
- 登录、上传、预览、分享和权限流程通过
- 备份任务成功，并在隔离数据库完成恢复验证
